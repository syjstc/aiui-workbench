# 官方平台草稿与提审

AI 准备应用代码、商店文案、图标、图片和视频，然后调用工坊 MCP / CLI。工坊执行上传、保存提审草稿、核对云端和用户确认后的提审。确认窗口要求用户确认版本与材料可公开发布；审核通过后的上架规则以官方平台为准，工坊不承诺平台另有发布确认步骤。

## 登录一次，复用官方会话

在桌面“构建与上传 → 登录官方平台”完成首次登录。官方页面使用独立的内存浏览器会话，与模拟器和预览来源隔离；官方 Cookie 和 SSO 状态仅以系统加密快照持久化，不写入普通浏览器 Cookie 数据库。桌面、Web 和 MCP 共用该会话，不分别要求登录。

登录 Cookie 到达后立即同步共享服务，并通过不含凭据的桌面事件刷新主界面，不等待定时轮询或用户手动刷新。会话同步并完成加密保存后自动关闭本次登录窗口。已经登录时按钮显示“打开官方平台”，主动打开的官网管理窗口保持打开，便于用户自行管理官网内容。登录为蓝色实底按钮，退出为红色边框与浅红背景，刷新使用中性色；浅色和深色主题均有对应配色。

“退出官方账号”关闭官方窗口和后台续期，清除独立会话的 Cookie/SSO/本地缓存及加密快照，并立即撤销共享服务授权和未使用的提审确认，停止运行中的平台任务。晚到的登录心跳不能恢复退出的会话。已发给平台的操作不能因退出而撤回，应核对官方状态。本机项目、包、资料草稿与回执保留；退出后隐藏账号记录，重新登录原账号后可继续查看。

## 两个标签页与统一应用

“打包与上传”集中放置本地构建、上传、提审草稿和提示。页面只选择一次本地应用，首次在“设置官方绑定”关联当前账号的正式智能体；后续各步骤共用绑定。已验证且目标唯一的旧上传回执会恢复此绑定，不按名称或本地开发 UUID 猜测。绑定只能由工坊界面设置，MCP 不能更改；服务端拒绝与绑定不一致的上传和提审。更改绑定后原提审确认失效。

“官网应用”直接读取官方列表，展示当前草稿、审核和已上架版本及资料，只读。列表没有编辑、覆盖或删除操作，也不提供云端删除 MCP 工具或接口。删除必须由用户前往官网操作。MCP 仍可上传新草稿、准备材料并请求用户确认提审。这里的官方记录与本机任务日志分开；清理任务日志不影响官网应用。

列表显示官方图标与介绍摘要；展开可查看完整介绍、意图说明、开场白、分类、权限用途和图片/视频预览，图片可放大。资料来自官方当前返回内容，缺失字段明确标注，不使用本地待提审材料冒充官网内容。包与代码摘要放在单独的详情折叠项中。

官网 Agent ID 在统一绑定、上传目标、官网列表和详情中完整显示为高亮只读区域，支持复制，不截断，也不与本地开发 UUID 混用。

两个标签页顶部共同展示实验功能警告，说明官方 Studio 接口可能变化、操作后需核对官网结果，结果不明时不得重复提交。列表为刷新时快照，不承诺实时推送或完整历史版本。

工坊通过 Electron `safeStorage` 使用操作系统密钥存储加密保存会话，在重启后恢复尚未到期的登录。Rokid 的时间戳令牌可没有 `exp` 字段，此时使用官方 Cookie 的真实有效期；不臆造平台到期时间。旧版浏览器会话会迁移到加密快照，并清理旧 Cookie 与已知登录缓存键。macOS 使用 Keychain，Windows 使用系统保护；Linux 的 `basic_text` 后端不视为可靠加密，改用内存会话。不保存账号密码，不将 Cookie、会话令牌、STS 或原生确认密钥返回给 AI、写入任务日志或打入安装包。加密文件只允许当前系统用户读取。

临近到期或平台拒绝旧会话时，工坊最多针对该会话尝试一次官方页面 SSO 续期，不刷新用户正在编辑的窗口。平台仍要求登录时，由用户完成；不模拟刷新令牌、不绕过验证码或强行延长失效凭据。官方窗口退出登录后清除加密缓存。桌面心跳停止后，共享服务的登录授权在 45 秒内失效。

## AI 工作流

1. `aiui_platform_status` 检查登录；首次登录由用户完成。
2. `aiui_platform_agents` 读取当前账号的完整列表，用正式名称和云端 Agent ID 选择目标。已有应用必须选择原商店身份，不能从本地开发 UUID 推断。
   在工坊为所选本地应用设置一次官方绑定；`aiui_platform_status` 的 `binding` 返回当前账号绑定，上传参数必须一致。
3. `aiui_project_build` 检查并生成当前源码和 SDK 的 AIX。
4. `aiui_platform_upload` 上传指定目标的草稿，默认递增云端版本并保留目标正式名称。只有云端目标、版本、包 MD5 回读一致，才返回 `uploaded: true`。结果同时保留本地 SHA256、源码和 SDK 指纹。
5. `aiui_platform_review_prepare` 上传素材、保存提审资料并回读核对。传 `description`、`prologue`、`versionLog`、可选 `iconFile`、`previewFiles` 和 `permissionUsage`。素材使用本机绝对路径；省略 `previewFiles` 时沿用现有云端素材。
6. `aiui_platform_review_request` 传 `projectId` 和返回的 `draftId`。此调用只将草稿设为 `awaiting-user`，工坊显示资料供用户核对。
7. 用户在工坊查看目标、版本、介绍、开场白、日志、权限、图片、视频和包摘要，点击确认，并在原生确认窗口提交审核。

长任务默认等待 45 秒，只有 `status: running` 才继续调用 `aiui_job_wait`。

```json
{"projectId":"<projectId>","agentId":"<cloudAgentId>","waitMs":45000}
```

```json
{"projectId":"<projectId>","description":"真实功能介绍","prologue":"首次进入的引导语","versionLog":"本次版本的具体变化","previewFiles":["/absolute/preview-1.png","/absolute/preview-2.png","/absolute/demo.mp4"],"permissionUsage":{},"waitMs":45000}
```

## 确认与失败边界

MCP 没有提交审核或发布工具，传入 `confirm: true` 不会取得用户授权。原生确认需要仅存在于桌面主进程和共享服务内存中的随机密钥，以及绑定具体草稿摘要、账号、版本、有效期的一次性确认凭据。伪造 `actor`、重放旧确认、修改资料、切换账号或改变源码都不能沿用原确认。

上传和提审请求不会在断线后自动重放。已发出请求但结果不明时持久记录为 `unknown`，阻止重复上传；用 `aiui_platform_status` 的 `reconcile: true` 回读核对。一次负面查询不能证明服务端不会稍后完成，因此不能据此自动重试。显式恢复需传 `resumeUploadId`，并保持同一项目、目标、AIX SHA256、版本和资料指纹；已验证的资源沿用，保存前再次核对云端。资源回执与保存结果分开保留。提审结果不明时应到官方平台核对。

图片须为 PNG/JPG，1 KB–5 MB；视频须为 MP4，1 KB–50 MB、可读取时长且不超过 60 秒。提审需要 3–5 个素材，至少一张图片和一个视频。工坊检查扩展名、文件头、大小和视频时长，使用官方 STS 的限定目录上传，并核对 OSS ETag。AIX 和从 AIX 提取的代码 ZIP 分别上传；代码 ZIP 只包含已打包文件，排除 VERSION 和 META-INF，避免将工程中的额外私有文件传上云。权限与本地项目一致，每项需有具体用途。

所有平台写入仅使用固定的 Rokid HTTPS 接口；素材地址限制为 Rokid 和官方 OSS 来源，不接受任意上传服务、凭据参数或自动跳转。首次集成依据 AIUI Studio 1.3.6 官方前端的 STS/OSS、`updateThirdAgent`、Studio 提交审核所用的商店接口契约；AIX 使用与 Studio 资源上传相同的 STS/OSS 流程，保存前后同时核对包和代码草稿摘要，不依赖未经确认的上传封装服务。这些不是工坊承诺稳定的公开 API。返回格式、身份或摘要异常时停止写入，不降级为猜测成功。模拟接口测试、真实账号草稿上传、真实提审、审核结果和上架分别记录。

平台会把代码草稿的 OSS 键扩展为临时签名下载链接。工坊验证官方来源与智能体身份后，只保留稳定的对象键；签名不进入 MCP 返回或提审确认摘要，避免签名轮换误判为云端代码变化。

现有资料保存接口不回传更新日志与 `needParam`，与 Studio 保留本地待提审内容的方式一致。工坊单独保存这些内容，展示其本地状态，将其与云端资料摘要一起纳入原生确认；确认提审时才通过商店审核接口发送。保存响应丢失后，刷新核对可以将已一致的资料恢复成可确认草稿，不再次保存或增加版本号。任何一侧的内容变化都会使原确认失效。
