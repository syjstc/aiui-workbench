# Rokid 镜腿离散输入规范

2026-11-09，根据镜中寻宝的佩戴反馈建立：**一次滑动只移动一个菜单项、翻一页或执行一次返回**。此规范用于后续 Rokid 项目和菜单修改，不表示其他现存应用已全部修复。

## 输入层统一处理

AIUI 宿主可能将一次滑动转换成多个方向键事件。本项目可用的 SDK 只保证按键 `code` 和按下/释放回调，没有可依赖的物理手势 ID 或触点结束通知。业务菜单不要直接消费每个方向事件。

- `ArrowRight / ArrowDown` 归为前向，`ArrowLeft / ArrowUp` 归为后向，别名交替不能重复移动。
- 有完整 down/up 时只在释放执行一次，长按自动重复不产生额外动作；同时兼容仅上报 keyup 的宿主。
- 同方向事件按连续输入合并。当前静默阈值为 **360 ms**；每个重复事件都延长静默窗口，因此长滑不会在固定冷却到期后再次移动。
- 不把绘制卡顿计为用户停手。真机首次绘制收藏页曾使同一连发序列的回调相隔超过一秒；当前在 `drawFrame()` 的 `finally` 中调用 `excludeBlockedTime()`，扣除同步绘制实耗，再等待 360 ms 可响应的静默。`event.timeStamp` 在本机存在，但不能据此推断所有固件都提供可靠的物理手势时刻。
- 反向立即生效，不强迫用户等完同向静默窗口。页面内部从菜单进入收藏等状态切换保留合并状态，尾事件不能继续翻页。
- 页面隐藏、销毁或返回卡片时复位。被合并的 keyup 仍需消费默认行为，隐藏页面和卡片不抢宿主输入。不要影响确认、系统退出等未接管的键。
- 日后 SDK 如果提供可靠手势 ID 或开始/结束事件，优先按物理手势去重，避免依赖时间猜测。

无原始触点边界时，静默窗口不能精确区分“一次长滑”和“极快的两次同向滑动”；后者可能被合并。不要声称时间阈值已经解决所有固件上的手势边界，必须在目标眼镜佩戴复测。

## 参考与验收

- 公开输入模块：[TempleNavigation](../examples/hello-aiui/lib/temple-navigation.js)。
- 完整 Page 接线：[Hello AIUI](../examples/hello-aiui/pages/index/index.ink)。
- 自动化：[输入契约测试](../tests/example-navigation.test.mjs) 和 `npm run qa:screenshots`，后者在真实 Ink 运行时回放长滑、别名重复、停顿后第二滑、反向、翻页与返回。

验收应覆盖完整 down/up、keyup-only、按住重复、超过一秒的长事件串、方向别名、独立第二滑、反向、页面切换尾事件及后台恢复。菜单和分页要一起验证。Canvas 重绘的项目需在每次同步绘制的 `finally` 中调用 `excludeBlockedTime()`；本仓库的简单文本示例没有大量 Canvas 素材，不能据此证明重绘繁重的应用已通过。

360 ms 阈值来自此前目标设备上的验证经验，不能推定所有固件和所有应用均已通过。模拟事件和 ADB 连发只验证输入接线；佩戴者的物理长滑、快速独立滑动和首次大量素材绘制仍须单独确认。
