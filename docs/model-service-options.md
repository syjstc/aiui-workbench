# 模拟器中的模型与网络服务方案

这是后续能力的设计说明，以下模型接入尚未实现。当前模拟器的网络开关发送在线／离线事件；`LanguageModel` 后端、语音服务和应用任意外网访问还未配置。应用调用 `LanguageModel.availability()` 失败时，联网状态显示在线也不能提供推理服务。

## 可选接入方式

| 方式 | 用途 | 限制 |
| --- | --- | --- |
| 工坊本地代理＋可配置视觉模型服务 | 电脑上的真实识图、流式提示与结构化输出 | 用户配置服务；需要鉴权、超时、取消、错误映射与连接测试 |
| 本地视觉模型 | 离线开发 | 效果、速度和内存占用取决于硬件与模型 |
| 固定响应回放 | 可重复的自动测试 | 显式标注模拟数据，不作为真实识图验收 |
| 眼镜＋手机端 Rokid 服务 | 最终设备体验 | 需要设备、手机和相应服务授权；电脑模拟不代替该链路 |

Ink Web SDK 已声明 `hostCapabilities.languageModel.getConfig()`，可配置 endpoint、API 协议和默认模型。工坊可在这一宿主接口后连接本地代理。密钥由本机服务管理，请求日志隐藏鉴权信息；应用需要相机图片时，应明确展示将传送的内容。

语音需要分别对接朗读和音频合成接口，避免只接入浏览器朗读后仍无法满足使用流式音频的应用。

## 通过 MCP 使用 AI 工具的模型

可以新增一个由普通 MCP 工具组成的请求队列：

```text
应用请求 → 工坊队列 → AI 工具领取图片和问题
→ AI 使用当前模型处理 → 回填结果 → 应用继续运行
```

建议按项目和预览会话隔离请求，包含请求 ID、图片、提示词、预期 JSON 格式、截止时间、取消状态和一次性回填凭据。AI 领取后返回结构化结果；超时、断线、旧会话或重复回填不能污染当前应用。

这种方式不需要工坊保存模型 API Key，但 AI 工具需要处于执行／监听任务中，调用会占用它的上下文、额度和推理时间。普通 MCP 连接不会自动唤醒空闲 AI，也不会自动提供音频合成。

旧版 MCP 的 sampling 允许服务端请求客户端推理，是否可用取决于客户端声明和授权。当前协议文档已将 sampling 标为弃用、计划移除，新实现更适合采用普通工具请求队列，并保留直接模型服务作为可选后端。[MCP 客户端能力说明](https://modelcontextprotocol.io/docs/learn/client-concepts#sampling)

建议先以公开示例完成“图片请求—真实 AI 回填—应用继续”的端到端验证，再对接具体业务；不把固定回放或模拟成功当成设备端服务已验证。
