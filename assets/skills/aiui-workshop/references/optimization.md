# AIUI 游戏与实时交互性能

## 场景设计时先做

- 按目标眼镜和实际视口选 Canvas 尺寸及帧预算。为实时画面维护一个调度循环和单调时间基准，按截止时间提交，错过的绘制槽直接跳过。输入和异步回调更新待处理状态，游戏时间和动作判定继续使用原有时间语义。
- 首屏只准备必需资源。按场景拆分图集和声音，优先把首个可玩场景做成可独立加载的一组。下一段地形生成或解码可利用准备阶段或有余量的帧间分小步做。只切换到准备完成且仍对应当前路线的结果，保留未命中时的正常回退。
- 给对象定义可见范围。投影或入队前剔除视口外、完全被遮挡或完全被雾覆盖的绘制项，覆盖静态道具和动态物件，保留雾的可见过渡和原有碰撞。稳定内容按变化频率更新，对比合批、缓存复制与跨层提交成本。
- 保留输入源时间和顺序，输入回调只做少量工作。需要缓冲时用有界队列，监测积压、陈旧样本和丢样。按场景管理传感器订阅和旧回调，复测连续动作的灵敏度。核对官方运行时能力后再用 Worker 或异步 API 卸载耗时工作。

## 优化时按症状验证

- 在实际入口分开测首屏、持续运行和事件尖峰。记录解码、逻辑、绘制、`flush`、音频提交、输入回调等待和帧间隔。看 P95、最长帧及具体触发事件，绘制耗时很低时也要检查调度和回调排队。
- 预热要验证命中率和每批耗时。对照首屏、普通跑动、密集战斗或 Boss、场景切换和长时间连续输入。逐项比较同一设备、宿主与场景的改动前后画面、交互时延和峰值内存。
- 如果短音效每次播放复制整个共享缓冲，准备时切成独立短片段，播放只提交当前片段。可延后的模型回包处理、音频合成或提交安排在关键画面提交之后，复测密集提示、声音顺序、循环边界和输入反馈。
- 分别记录应用 Canvas 提交、系统实际呈现、佩戴操作及手机 AR 录制。打包后确认 AIX 含优化使用的资源和代码，开发诊断入口随正式构建排除。包体压缩另见 [素材优化](asset-optimization.md)。
