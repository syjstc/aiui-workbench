# AIUI 项目排查经验

适用于工坊及其连接的 Codex、WorkBuddy 等 AI 客户端。按当前任务选择相关条目，不逐项重跑所有检查。这里记录近期项目中经源码、运行日志或对照实验确认的经验；具体 API、权限和语法仍以项目绑定的官方 `aiui-dev` 为准。

## E01 · 配置存在，当前聊天却没有工具

**案例：WorkBuddy 五子棋、工坊升级。** 写入 MCP 配置、stdio 握手、客户端注入工具、成功读取工坊上下文是不同状态。WorkBuddy 曾在配置正确、服务正常时仍没有当前聊天可调用的 AIUI 工具；首次连接另有客户端信任步骤。

- 先区分配置、信任、服务和聊天缓存。配置文件路径及刷新方法按当前客户端确认，不照搬另一个客户端的路径。
- 以实时 `tools/list` 和成功的上下文调用确认能力；工坊服务、Ink 引擎、Web SDK、CLI 是不同版本。不要因 SDK 版本较低或一次超时就重装工坊。
- 客户端要求信任时，说明具体界面操作。已授权且具备终端能力时，可用工坊公开 CLI 完成工作；它与桌面/MCP 共享任务，但不能据此声称客户端的 MCP 已连接。不要为绕过信任而重放私有 HTTP、读取会话口令或修改客户端安全设置。
- 恢复后沿用项目和 workflow，保留现有配置。工具未刷新时重连或换聊天；不要反复创建应用或安装同名 Skill。已有上下文按需复用。

## E02 · 应用正常，行为断言却一直失败

**案例：WorkBuddy 两轮五子棋。** 启动日志早于第一步观察窗口；电脑回应可能已在落子步骤内完成，下一步再等同一条日志会失败。

- 工坊日志断言只匹配本步骤动作开始后的新日志，并校验运行实例。先看失败报告的步骤、`startedAt`、run/revision 和实际日志；不要把旧会话的成功记录混进新一轮。
- 启动行为可在显式 `reload` 步骤观察；已存在的状态用实际可读状态核对。落子及异步电脑回应放在触发落子的同一步中，用足够的 `settleMs`/`timeoutMs` 和日志断言覆盖；需要精确次数时等待整个有效观察窗口。
- 不为通过断言而修改产品的走子延迟、反转方向、放宽为无关日志，或把应用健康冒充功能正确。先前“wait 不观察日志”的临时猜测不能当成规则：当前实现将 wait 映射为 observe，仍按同一窗口过滤。
- 姿态、模拟存储等可能跨回放保留。先建立明确初始状态，再测试变化、静止保持及恢复；不能靠清空日志或盲跑两遍掩盖失败。运行时没就绪时检查预览宿主是否仍打开。

## E03 · 单击变长按，一滑移动多项

**案例：WorkBuddy 首轮五子棋、头号寻宝家菜单。** 只有 keyup 时，拿 `now - 0` 计算按住时间会误判超长按；宿主还可能为同一滑动发送重复方向别名。

- 确认键没有匹配的 keydown 时按单击处理；重复 keydown 不重建长按计时器。长按已触发后，释放不能再落子。隐藏、销毁及卡片/全屏切换清掉按住和长按状态。
- 方向键优先复用项目的离散输入模块：归一别名，同方向重复刷新静默窗口，消费合并事件，反向操作按项目约定处理。不要靠固定冷却周期让长滑再次触发。
- 可信原始事件时间优先；同步绘制阻塞不算停手。首次大量素材绘制、页面内切换的尾事件也要覆盖。
- 至少核对完整 down/up、keyup-only、长按释放不落子、长滑/别名只一步、停顿后第二滑、反向、翻页和返回。阈值来自目标项目验证，不是所有固件的通用常数。
- ADB 的确认键和物理镜腿可能走不同路径，`--longpress` 的实际时长也可能低于应用阈值。读真实前后台状态和应用事件日志；不把注入成功说成佩戴通过，不硬编码另一台设备的 `/dev/input/eventN`。

## E04 · 转头输入覆盖镜腿选位

**案例：WorkBuddy 第二轮五子棋自主运行检查。** 高频姿态读数会立即把镜腿刚选中的格子改回头部指向，即使两种输入分别都能工作。

- 明确输入优先级及重新接管条件：例如镜腿操作后短暂保留选择，或直到头部进入另一格才重新接管。参数按产品体验确定，不把示例的毫秒数当标准。
- 分别记录选择来源和最终选中项。测试静止头部时滑动、滑动后持续读数、重新转头、落子，以及隐藏/恢复。
- 头部数据采样、视图投影和手势识别分别管理。寻宝挖掘画面需要固定时，只冻结显示投影；原始姿态仍用于点头识别，恢复寻找时从当前姿态重新建立基准。

## E05 · 姿态停不下来、恢复不了或方向相反

**案例：WorkBuddy 首轮源码修正、工坊与多款 3DoF 游戏。** stop 后未清理的 sensorReady 标志会挡住 onShow 重启；滑条变化、收到读数和画面方向正确也是三件不同的事。

- stop 时同步清理实例、监听和启动守卫；show 后重新获取有效读数并校准。迟到回调须属于当前实例。校验时间戳及数据新鲜度，重复旧读数不能刷新有效期。
- 先确认当前模拟器/设备四元数顺序、坐标系和安装基准，再检查应用的相对姿态及逆相机变换。固定世界物体在转头时应向视线反方向移动；选位光标的产品规则可能不同。
- 不凭一次模拟现象全局翻轴，也不采用 WorkBuddy 早期互相矛盾的 yaw 猜测。逐轴双向、组合旋转、归零、hide/show 都要核对应用实际结果；当前模拟器方向约定见 [verification.md](verification.md)。真机方向仍需佩戴确认。

## E06 · 工具能打开，语音却进错应用或只开卡片

**案例：万物捕手、头号寻宝家、八荒战舰、弯道之间。** 历史 AIX 打包器曾因首屏公开 schema 参数导出 `_current`，静态布局不完整还会推导出较矮的工具尺寸。提示词里写“全屏”不能修正实际导出元数据。

- 交互应用按用户约定设置唯一首入口，检查实际 AIX 的工具定义：路由、`target=_blank`、参数和目标布局。480×352 是此前 RG glasses 的目标尺寸；不要推广到 Widget 或其他设备。
- 此前可用做法是首屏公开参数为空、诊断通过开发 query 传入、根布局尺寸明确；升级打包器后重验实际产物，不把旧版本行为当永恒规则。
- 语音链路分开查 ASR 文本、匹配到的 Agent、工具调用、实际 surface。明确名称和打开意图，识别旧测试 Agent 冲突；处理旧身份须保留数据并遵循授权。
- 开发启动、安装回读、手机上传 ACK 都不能替代真实语音启动。保留应用身份，按各阶段回执报告进度。

## E07 · 模型可用，但请求失败或结果不能使用

**案例：WorkBuddy 五子棋、头号寻宝家识别、万物捕手联网。** 能力探测 available、发起请求、收到有效结果、把结果显示到当前页面须分别证明。五子棋有启动与长按两个调用来源，不能用启动成功替代长按链路。

- 用请求来源/ID、实际返回和画面高亮验证同一轮操作。确定性本地算法可降级，但界面和报告标明“本地”；不把本地推荐或模拟回复叫真实模型验收。
- 校验结构、坐标范围、目标身份及当前状态；响应已过期、页面隐藏、棋局/照片已变时丢弃。能力缺失、超时和格式失败分别给出可恢复反馈。
- `Failed to open IPC socket: connect timeout` 等先查官方手机 App 与眼镜代理连接。Android 默认网络为空不能证明 SDK 不能联网；万物捕手曾在手机蓝牙代理接通后真实请求成功。以请求结果验证，不要求用户先给眼镜配置 Wi-Fi。
- 识别评分不是校准准确率。高分还须结合清晰度、可见范围、类别一致及目标尺寸；不合格时允许重拍，不为完成教学补造奖励。阈值和实际误识别率分开记录。
- 普通模拟器的 AI 服务能力按实时清单确认。缺失时保留其余行为检查，再明确转真机；临时 AI 自动化接管按 [simulator-ai.md](simulator-ai.md) 的适用范围使用。

## E08 · 拍照成功，重试黑屏或旧结果回来覆盖新页面

**案例：万物捕手取景、保存和删除流程。** 取景流、一次拍照、识别、缩放和持久化有各自的成功/失败状态，不能把它们绑成一个“完成”开关。

- 页面可见性及操作代次约束异步回调。隐藏、重试或换来源后，旧相机/模型/缩放结果不得恢复旧画面；释放流与监听后，重试需能重新申请。
- 有效原图先显示，背景缩放成功后再替换；不要先卸载原图。权限拒绝、取景→定格→失败→重试、hide/show 均需检查。
- 保存失败保留待保存结果；删除先可靠提交索引/清理意图，再清无人引用的媒体，失败可恢复。不要把界面返回当成持久化成功。
- 本地照片与电脑摄像头只证明模拟帧链路。手机 AR 录制占用相机时的冲突须单测，不能用电脑取景成功替代。

## E09 · 音频参数被网关拒绝，或离页后仍在说话

**案例：头号寻宝家 TTS、八荒战舰音乐、万物捕手简介。** 寻宝所用语音网关曾对小数 speed 返回 HTTP 400，只接受实测整数 1、2；这不是所有 TTS 服务的参数规则。

- 按当前提供方验证值域及错误响应；记录实际接受值，不只依赖接口类型。每句等待真实播放结束再衔接下一句，隐藏/退出同时取消生成、队列和播放器。
- `Sound`、`AudioPlayer` 与浏览器音频接口不同；循环、暂停和事件要查对应官方媒体参考。复用播放器，加载完成回调重新检查页面和静音状态，失败不逐帧重试。
- 请求日志、合成时长、播放器回调和实际听感分别说明。参数请求成功不证明扬声器听感已通过。

## E10 · 加载卡与 AR 录屏掉帧是不同问题

**案例：来捉我吧。** 首页大量 RLE 素材同步逐像素解码是经计时定位的启动瓶颈；批量填色在隔离 Ink 模拟器中约从 6.8 秒降至 1.1 秒，图像字节及首页 PNG 一致。早期只修改内存实验包，之后才有源码 0.5.6，不能混用两者。

- 先分段计时加载、解码、控制器初始化和绘制；定位后采用批量操作或按需缓存，保留字节序、缓冲区偏移及旧宿主回退。确认改动已进入真实源码和最终包。
- 缓存稳定 HUD/几何，给缓存上限；持续变形且只用一次的路径不宜每帧建立原生缓存。优化后比较代表性画面，避免以改变效果换取未经说明的性能数据。
- AR 录制应在同一场景做录前/录中/录后对照，同时看逻辑、绘制、姿态回调及系统负载。应用绘图提交次数不是屏幕呈现/编码有效帧率，flush 返回也不是编码完成。
- 多轮录制中仍有严重下降，更换 rAF 或删除音频都未形成稳定修复。需要故障发生期间的原生调度证据；停止录制后采到的追踪只是基线。不能用一次正常录制或模拟器启动提升宣布录屏问题解决。

## E11 · 升级成功，数据或正式身份却变了

**案例：多款游戏原位安装、万物捕手云端包。** 本地项目、开发 Agent、云端 Agent、应用版本、商店版本及每次构建 VERSION 不等同。

- 修改现有应用沿用原身份和存储键；需要数据迁移时先确认已有格式和失败恢复。安装后回读版本/运行标记、代表性文件及原有进度，不用卸载重装代替排障。
- 本地打包、开发安装、云端草稿、提交审核、上架分别以回执核对。云端重新打包可能只改变 JSON 格式，应比较运行文件及 JSON 语义，同时检查入口与资源。
- 结果不明先查询，避免重放上传/提审。平台登录与应用绑定是不同前置条件；五子棋有过已登录但未绑定应用的情况。尊重用户当前任务范围。

## 记录新经验

新增条目至少写清：触发条件、可核实的根因、最小修法、如何验证、适用版本/设备及尚未证明的部分。区分 AI 自主验收发现、用户反馈后 AI 定位和 AI 自己的误判；未验证的猜测留在该项目诊断中，不升级成全局规则。不搬入账号、口令、设备标识或私人路径。
